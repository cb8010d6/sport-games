# #52：回合与派对大赛的中断恢复

状态：设计与范围记录；实现、复现回归和实际画面验收尚未完成，关联 PR 保持 draft。本记录不代表 #52 已修复。

## 问题与范围

以 dev `c6c0668` 为起点检查，射箭 SHOOT 仍要求所有箭用完，保龄球 AIM 没有截止时间；大赛大厅仍要求在场人数等于原始参赛人数；大厅和成绩页的 C 仍直接调用清空大赛的 `go_menu()`。

这是一次针对 #52 的跨区修改：射箭和保龄球负责本项目的出手时限与零分结算；`RSPartyGame`、`RSPartyUi` 和 `RSTournament` 负责大赛缺员、现有积分与退出确认。测试与运行器覆盖真实场景调用路径，翻译只追加相关文案。先记录本设计及架构，再改运行时代码。不改手柄协议、存档格式、autoload、引擎版本或依赖；不把保龄球场馆返工 PR #31 包进来。

## 拟定行为

1. 射箭每支待射箭有 20 秒有效比赛时间，按键反复按下、断线或重连不重置时限。到期未出手按 0 环消耗这一箭，取消未释放的拉弓状态；已经飞出的箭按原物理结算，不能超时后再重复扣箭或加分。
2. 保龄球每次准备投球的 AIM 最多 20 秒；到期消耗一次 0 瓶投球，复用正常计分和换球／换格规则。原 SWING 最长 6 秒自动出手与 ROLLING／SETTLE 的有限时长保留，进入 SWING 不得重新获得另一段 AIM 时间。首球超时不清空仍站立的球瓶，第十格加球仍按正式规则处理。
3. 大赛允许在场的原参赛者全部准备后继续，不要求缺席者回到大厅；至少一名在场玩家才能开局。缺席者本项目加 0 大赛积分，保留此前积分及原始参赛槽位，后续项目可以重新加入；在场玩家按其本项目实际竞赛名次获积分。大厅与成绩明确说明缺席计分规则，不把缺席者当成并列最后一名发保底分。下一项缺席与比赛中保留槽位是不同情况，不能靠移除 PLAY 玩家规避两个项目的时限。
4. 大赛未完成时，大厅／成绩页首次 C 只显示退出确认；只有同一有效在场手柄在 3 秒内再次 C 才返回菜单并清空大赛。其他按钮、切换阶段、重开或该手柄断线取消确认；不能由两个不同手柄的一次误触凑成确认。普通单项目仍沿用一次 C 返回。暂停菜单明确选择“回菜单”的现有路径保留。
5. 所有玩法时限使用现有 `delta`／阶段时钟，树暂停即冻结；重开、换箭、换球及换项目必须重置对应状态。演示机器人和 benchmark 不获得额外分数，也不写玩家纪录。

## 复现与验收

保留修复前后的独立输出，不跳过失败或改写旧结果：

- 生命周期：射箭、保龄球各 2／4 人，PLAY 中 P1 断线不再回连，以及连接但完全不操作；其他人正常推进，两项目须在有限模拟时间内进入 RESULTS。
- 边界：截止前／到期／截止后出手，反复按键、迟到 release、重连、暂停、重开；射箭飞行中只结算一次；保龄球首／次球、全中／补中与最后一格加球，不得把旧瓶误计为新超时击倒。
- 大赛：第一项正常完成，第二项移除一名参赛者，剩余玩家准备后继续第三项；核对缺席者原积分不丢、本项 0 分、在场者名次积分、下一项重连及最终领奖台。零人在场始终留大厅。
- 退出：LOBBY／RESULTS 单次 C 不清空；同手柄有效二次 C 才清空，超时／不同手柄／断线／其他操作不串联；普通单项目行为不变。
- 使用官方 Godot 4.7.2 跑受影响的实际双人／四人回合、相关 lifecycle／party-flow、公共 smoke；中英文实际渲染检查倒计时、缺席提示与确认提示，不能用 headless 结果宣称画面通过。
- 工具单元测试、规范、i18n、素材工具、隐私检查和必要 CI；测试用五个隔离用户目录并检查 `records.cfg*` 未写入。

## 已实现

| 功能 | 行为与实现入口 |
|---|---|
| 玩家档案 | `core/profiles.gd` 保存四个稳定玩家槽的名字、颜色、角色；滑板、滑雪、篮球使用所选外观 |

| 派对大赛 | `core/tournament.gd` 管理 3–6 项、固定玩家槽、名次积分、并列名次、防重复计分和最终二维领奖台 |

## 引擎源码修复（2026-10-22）

独立测试在主线程与四个工作线程上同时创建 / 释放网格、多网格、着色器、材质与纹理。原版 Godot 4.7.2 的网格、材质各三次均以 `0xC0000005` 崩溃，纹理三次均有 RID 错误或泄漏。测试不含游戏素材、自动加载或编辑器插件，确认这是可独立复现的引擎缺陷。

已将上游 [#121958](https://github.com/godotengine/godot/pull/121958) 的五处线程安全修复回移到同一 4.7.2 源码，使用校验后的便携 LLVM-MinGW 和独立 SCons 环境编译出 `4.7.2.stable.regina_ridfix1`。补丁、Godot MIT 许可、固定版本构建信息与说明在 `tools/engine_patches/`。`tools/build_godot.py` 先测试打包后的引擎，通过后才安装；原版保留，完整调试符号留在本地源码构建目录。

安装后的修复版三类并发测试各跑十次，合计 30 次全部通过，无原生失败、RID 错误或泄漏。另已通过完整游戏资源导入、两次开启并行导入的新缓存代表资源导入、存档读回与三场连续派对流程，以及全部 10 组地图四人完整无头回合。飞机四人英文 Vulkan 图形回合也已通过，1600×900 结算截图已检查，四个分屏与结算列表正常。

Python 导入 / 测试工具会优先使用本地修复版，显式引擎参数和环境变量仍优先。此便携构建包含 Vulkan / OpenGL / Jolt / 3D，未包含额外 SDK 对应的 D3D12、ANGLE、AccessKit、WinRT，普通启动器继续选择完整官方版。尚未构建修复版的机器保留串行导入规避。手动触发的引擎构建及 30 次压力回归工作流已提供，未在远端执行。

旧 Windows 弹窗没有调用栈，仍无法证明每次都来自这处并发缺陷；本次已直接修复并验证的是上述可复现的引擎资源分配问题。

## 建议优先级

1. **先完成验证闭环**：六项目全部地图 × 2 / 4 人无头回合已通过；下一步补开始 / 暂停 / 重开 / 返回操作、三种手柄的长局、断线和重连验证。补教学与六项目四人布局截图；工具已支持单张 SVG 总览。当前派对总领奖台是公共二维界面，未来可接统一三维演出。
2. **补单人体验并验证教学**：教学框架已接六项目，下一步用手机 / Regina 校准提示和阈值；正式电脑对手提供三档难度；每项目设三个挑战目标与星数。先选一个项目打通，再推广。
3. **完成音频和演出**：选择可核实来源的 CC0 菜单 / 大厅 / 胜利音乐；把滑板、滑雪、篮球重复的开场、回放和领奖台抽成公共模块。主菜单还缺预览图。
4. **用测量推进性能**：固定参考硬件、分辨率、路线和机器人种子，记录 CPU / GPU 帧时间；据结果调整分屏阴影、LOD 和 FSR，不用未测数据宣称达到 60 fps。
5. **提高存档与构建可靠性**：增加存档版本、迁移、备份和损坏恢复；锁定 Python 依赖与工具链版本；建立 Windows 原生失败日志 / 转储收集。发布前重新跑许可和素材完整性审查。
6. **最后扩内容和发行**：先写高尔夫的挥杆、推杆与计分设计；再做其他新项目。主线已提供 Godot 导出、hub 打包和便携包工作流；需验证本轮功能在实际发行包中的完整流程，再做安装包与渠道配置。

后续迭代应保留上述验证边界；完整回归通过后再更新相应 TODO 状态。

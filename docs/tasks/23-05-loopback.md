# 23-05 · 双实例回环验收

## 目标 / 范围外

一条命令在同一台电脑拉起两个官方 Godot 4.7.2 无界面实例，完成滑板和滑雪的房间、开局、幽灵、结算和回大厅串联验收。实际 Wi-Fi、画面和手感另由维护者试玩。

## 先读

1. [LAN_PLAY.md](../LAN_PLAY.md) 第 6 节及附录 B
2. [23-03](23-03-ghosts.md) 和 [23-04](23-04-discovery-menu.md)
3. `tools/test_hub_port.py`、`tools/engine_process.py`

## 改动文件

- 新增 `tools/test_lan.py`、`tools/tests/test_lan_runner.py`，新增 `game/tests/test_lan_peer.gd`、UID、同名场景。
- 若源码需要让测试观察已有事件，只改 `game/core/net_session.gd`、`game/core/net_remote.gd` 的对应观测和 `docs/ARCHITECTURE.md`、`docs/protocol.md` 的相关段。

## 接口契约

- 两端显式绑定并连接 `127.0.0.1`，临时监听端口、隔离用户目录、`RS_TEST_MODE=1`。只停止 runner 启动的子进程，设定超时并保存每端日志。
- 一份最小结构化摘要报告双方实际阶段、座位、开始时间、幽灵与结果，以及退出或失败原因。同一个 PR 交付生产者、读取校验和测试。比较跨进程时间时使用独立共同参考；参考精度不够便标明未验证。
- 正常结束要见双方回大厅；硬杀的一端只记录进程退出和已有检查点。幸存方正常识别断线的证据不能补成被杀实例的成功报告。
- 先跑正常回环、同一场次重发完赛和主机退出三条路径。有注入时标明是应用层延迟或快照丢弃；更完整的延迟矩阵和发布摘要留给后续。

## 依赖与顺序

依赖 23-03、23-04。

## 验收

实际双实例验证两项运动各能走完整流程，确认同一事件不会重复计分、主机退出后客户回菜单。失败路径保留日志并返回非零退出码。自动化只用本机，双机试玩结果独立记录。

## 不要做

不访问外部网络，不替换现有正式发布流程，不把脚本报告当作真机验收。

## 预计规模

一个 runner、一个测试场景及其小型自动测试。

# 23-02 · 开局流程与结算

## 目标 / 范围外

主机能开一局滑板或滑雪，所有客户端在同一起点开始，收到统一成绩，回同一个房间。项目幽灵和正式菜单在后续卡实现。

## 接口契约

- 只有主机能开局。所有参赛者已准备，时钟已同步，主机发地图和种子，确认双方地图摘要和加载成功后发未来倒数起点。加载失败或超时回大厅，旧局消息不能推进新局。
- 开局冻结全局座位；退赛后号码不重排。主机按有效完赛收到顺序分配名次奖励，使用现有项目的奖励规则。发送方的本局 `EventId` 保持不变；收到同一事件重试时，主机重新确认已有名次，不重复加分。相同 ID 但内容冲突时拒绝。
- 客户端按主机结果显示全局名次；重复结果只结算一次。LAN 暂停显示覆盖层，比赛时钟继续。客人离开不阻塞主机，其成绩不入最终排名；主机离开时其他人退出到菜单。
- 非 LAN 仍使用原有流程。 `RSPartyGame` 的本地玩家、相机和回放保留本地槽；LAN 不写个人纪录或派对积分。项目调用仍使用 `send_event(kind, data)`。

## 依赖与顺序

依赖 23-01；向 23-03 提供阶段、名次、倒数和完赛事件接线。

## 验收

用模拟时钟和无界面回环覆盖加载失败、重复/冲突完赛、重复结果、客人退出、主机退出、返回大厅后的下一局，以及非 LAN 的原有结算。

## 不要做

不调整计分规则或改 UI、派对大赛、hub 协议和存档。

## 预计规模

一次交付开局到回大厅的流程，场景测试复用前卡会话。

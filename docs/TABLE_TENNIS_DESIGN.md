## 集中确认的默认决策

1. 1 人对电脑、2 人单打、3–4 人双打；3 人补一名电脑；按本稿的固定配对、轮流击球和队伍名次结算。

5. F5–F7、F10 与共享素材缺口先由主线提供；T1 临时简化弹道不能变成第二套公共球模块。本文的接口需求、输入参数、辅助发球和预算均待确认。

## 人数、队伍与一局流程

以本局真人槽号升序记 H1–H4；A/B 是队名，不代表手柄按键。大厅显示配对，准备后锁定；中途不加入、不重分队。

| 真人数 | 对局与配对 | 视口提案 |
|---|---|---|
| 0 | 不开始；纯 demo 除外。 | 大厅。 |
| 1 | H1 对普通电脑；正式 `RSSolo` 使用所选三档，复用其唯一对手，不再补第二个电脑。 | 仅真人 1 格；需 F5 将电脑实体与视口分离，现 solo 会给电脑也建一格。 |
| 2 | H1（A）对 H2（B），1v1。 | 左右分屏，双方均从自己端线后看球。 |
| 3 | A=H1+H3，B=H2+电脑；补位电脑固定普通档。 | 真人占 3 格，第四格留空；电脑不占真人槽号、不取档案外观/纪录身份。 |
| 4 | A=H1+H3，B=H2+H4。 | 四格；同侧两个镜头仅轻微错位，规则世界和球共用一份。 |

`--demo=2/4` 分别用 2/4 名机器人模拟对应数量的展示视口；F5 不得因隐藏补位视口而把 demo 的测试布局也隐藏。
PLAY 内状态为 `SERVE_READY → TOSS → SERVE_FLIGHT → RALLY → POINT_CARD → SERVE_READY / MATCH_OVER`；公共 Phase 不增加。
开局发球队用独立种子抽取，队内最小稳定参赛编号先发、另一队最小编号先接；不增加大厅选发球功能。每分卡 0.8 s，随后发球准备限时 8 s，超时发球方失 1 分。
240 s 从进入 PLAY 起累计，含发球等待、抛球、重发、回合和分间卡；暂停不累计。不得每分重置或以循环重发绕过限时。
比赛掉线需求：F5 保留参赛实体与比分，取消候选并冻结本拍，最多给 5 s 重连宽限，宽限计入 240 s；恢复重发本分，发接球轮次不变。
宽限超时判该队弃权；双方都无真人在线则取消本局、无派对积分；弃权/掉线局双方均不写个人纪录。重连不生成新队员或额外球；此政策需 F5 支持，不能靠删改 `players` 临时实现。

## 计分、发接球与判定

本节为本项目的规则适配提案，不宣称完整实现官方赛事规则。器材比例已核对 [ITTF 2026 Statutes，第 2 章](https://db.ittf.com/sites/default/files/public/2026-02/2026_Statutes_v1_consolidated_tc.pdf#page=39)：台面 2.74×1.525 m、台高 0.76 m、网顶距台面 0.1525 m，球直径 0.040 m、质量 0.0027 kg（2.1.1、2.2.3、2.3.1–2）。
发球/轮流击球参考同源 2.6、2.8、2.9、2.13；15 分封顶、240 s 和局、辅助发球、不换边及简化犯规均是游戏提案，不能称为 ITTF 标准。

| 条件 | 唯一处理 |
|---|---|
| 常规终局 | 任一队至少 11 分且领先至少 2 分即结束；若先到 15 分则无须净胜 2 分。11:9 结束、11:10 继续、14:14 下一分以 15:14 结束。 |
| 240 s 截止 | 只处理事件时刻 ≤240 s 的接触/得分；截止仍在飞行的本分不计，立即冻结。领先者胜；平分和局、双方无胜利奖励，不补赛。 |
| 单打发球 | 每 2 个已计分回合换发；10:10 起每 1 分换发，延续原轮次；let 不消耗发球次数。 |
| 双打发接球 | 设首发 A1→首接 B1：发球组依次 A1→B1、B1→A2、A2→B2、B2→A1，再循环；每组 2 分，10:10 后每组 1 分。 |
| 双打击球 | 每分从当前发/接者起循环“发者→接者→发者队友→接者队友”；HUD 明示“该你接”。未轮到者空挥只提示等待，不提交击球；规则收到越序实际接触则该队失分。 |
| 发球落点 | 抛球自动向上 0.20 m、无初始旋转、下降时拍击；先落本方再落对方台面。双打须本方右半区→对方右半区，中线归右区；单打不限制半区。 |
| 发球擦网 | 后续落点合法才为 let，比分/发球轮次不变；落点不合法仍失分。一般回球擦网后合法落台继续。 |
| 正常回球 | 必须先在接球方台面反弹一次再回击；落到对方有效台面才完成合法回球。接球方两跳未回、提前截击、连续二击或越序接触均失分。 |
| 出界/台边 | 未先落对方有效台面而触地/场外物即击球方失分；上表面边线与上沿有效，垂直侧面无效；球仅飞出台面投影不能立即判界外。 |
| 重复事件 | 每个球、每分及接触具有递增 ID；规则终态锁住后不再加分、发奖或重调 `finish_round()`。无球/NaN/碰撞迭代耗尽为测试失败，不能伪装成正常得分。 |

规则唯一所有者是拟新增 `RSTableTennisRules`：持有队分、发接轮次、预期击球者、落台计数、let、截止与终局。F6 不决定得分，HUD、机器人、人物动画都不得改规则状态。
F6 同步骤内先按接触时刻排序；同时刻按稳定碰撞体 ID 处理，已终态事件丢弃；台面/侧面/网缝的边界归属须在 T2 固定测试中锁定，不能靠帧率或回调顺序决定。
身体碰网/扶台、裁判警告、暂停次数、官方轮椅特殊条款和完整发球遮挡审查不模拟；自动站位保证不穿网，教学明确这是一局制的体感适配。

队员最终 `p.score` 同队相同，得分期间先显示原始 0–15 比分，胜利奖励只在终局一次加入；11:9 为 3100/900，15:14 为 3500/1400，限时 7:7 为 700/700。
F5 需按两个队生成名次 1/2，再展开到真人：胜队每人第一名积分、负队每人第二名积分（当前 `RSTournament.POINTS` 为 10/7），不能因双人并列变成 1/1/3/3。和局两队并列第一，各真人 10 分；电脑不入派对积分表。
个人纪录提案：项目重写已有 `can_record(p)`，在 `super` 许可之上仅允许正式 `RSSolo` 真人、无掉线/弃权/调试的完整终局；双打和普通多人局只记本局明细，不混入个人榜。
复用 [RSRecords](../game/core/records.gd) 的地图/槽号键及“仅更高分覆盖”；地图分榜、旧档缺项为 -1、同分不覆盖。胜负和原始比分只作本局明细，不额外存文件。
现 [RSSolo](../game/core/solo.gd) 星数仅从地图索引 0 的个人最佳积分推导，无模式/难度条件。默认挑战为“500 / 1000 / 3100 对局积分”，低比分限时胜利也可跨过前两档；不冒称“11 分内赢普通电脑”。若要限定难度或净胜分挑战，先另评公共目标/纪录接口，不能私存进度。

## 自动跑位与体感输入

自动跑位查询 F6 只读预测的首次可击球点，提前移动到本方端线后可达区域；初值移动上限 3 m/s、加速度 12 m/s²。双打非接球者退出击球通道，不能替队友自动接球。
预测不是保证命中：过远、速度不及或没有有效挥拍均可失误；角色脚步与拍位连续移动，不瞬移球或直接改落点。正反手按球相对持拍肩的横向位置选，±0.08 m 死区保持上次动作，避免抖动切换。
玩家 IMU 只提供姿态和运动强度；虚拟拍心由自动跑位/动作模型提供，F6 以虚拟接触点求响应，不把加速度长时间积分为现实空间位置。

| 操作/阶段 | 默认行为 |
|---|---|
| 大厅、成绩、D | A 准备/重来，B 大厅选地图，C 回菜单；D 短按公共暂停、长按由 hub 回中，沿用外壳。 |
| SERVE_READY | 仅发球者按 B 抛球，一次按下只建立一个 toss ID；无新鲜输入不抛。A/C 在 PLAY 不承担其他功能。 |
| TOSS | 有效挥拍可击球；松 B 请求固定力量 0.35、无旋辅助拍，但仍需按住≥0.15 s、新样本及下降段窗口；过早松开只等待最多 0.35 s，未进窗口则无拍，球落下判发球失误。 |
| 发球去重 | 挥拍先成功则消费 toss ID，后续松 B 不再击球；辅助发球仍经 F6 拍击和发球落点规则，不直接发送得分或“必定合法”弹道。 |
| RALLY | 无须按 B；每个挥拍候选至多消费一次。初始容错窗口为预计触球时刻±0.12 s，“好”为±0.04 s，其余为“早/晚”；窗口外空挥不自动回球。 |
| 暂停/回中/重开 | 清候选、探测器门控和待松 B；暂停冻结球与比赛钟，恢复要求新挥拍，发球态需先松 B 再重新抛同一分；重开清比分、球、种子游标、回放及终态锁。 |

F7 初值：沿用探测器 5.0/1.5 rad/s 起止阈值，`end_hold=0.06 s`、`min_duration=0.05 s`；这些是校准起点，不是已验证的真机手感。F7 须区分朝球出拍与向身体回摆，回摆不出球；正反手均允许，不能用单一正轴门槛排除反手。
力量 `P=clamp((peak_rate-5)/7, 0, 1)`，拟映射拍速 2–8 m/s；上/下旋由击球时 `motion_orientation()` 相对回中拍面的俯仰（±30°）映射至±80 rad/s，侧旋由 `motion_roll()` 的相对扭转（±30°）映射至±50 rad/s。
早/晚时差连续映射至相对对方球台左右方向±20°，中心拍取中路；两端玩家转换到各自球台坐标，不能共用世界左右符号。最终速度/旋转由 F6 的拍面响应限幅；具体系数在 T2/T3 联调后锁定。
输入必须走 [RSController](../game/core/rs_controller.gd) 的 `motion_orientation / motion_pose / motion_gyro / motion_roll`；`RSSwingDetector.feed()` 已镜像姿态和角速度，不再镜像第二遍。左右手切换另镜像人物持拍侧，但等效动作须有相同力量和对应落点。

### 新鲜度与时钟域契约（F7 前置）

- 从 `ControllerHub.samples_received(c, count)` 处理全部新增样本，逐人保存消费游标/epoch；按渲染帧取最新峰会丢数据，同一峰不得同时发球和回球。
- `sample_time / hist_time / swing.peak_time` 是 hub 秒，`phase_time` 是游戏阶段秒；`peak_time - phase_time` 无意义。按键包当前无 hub 时间戳，不能声称知道设备按下 B 的精确传感器时刻。
- 默认接收顺序门控：B 到达时保存已消费样本游标；只接受之后到达、hub 时间严格递增的新样本。F7 须输出候选的 hub 时间、接收游戏时刻、epoch 和映射后的固定步编号，签名由主线确认。
- 批内相对时间以 hub 差值保留：以批末样本的接收游戏时刻为锚，减去“批末 hub 时间−候选 hub 时间”；不把跨机器绝对时间相减。它不补偿未知网络延迟；延迟误差留给 T3 真机评估，不偷偷改协议。
- 用游戏本地单调接收钟计输入停更：0.30 s 无递增样本即取消候选；重复/倒退、跨度>0.10 s 的积压批、断线/暂停/回中都失效并换 epoch，不能新包一到就复活旧峰。
- 样本只排队到尚未推进的固定步；晚到且已过窗口的候选丢弃，不倒带球、不改旧比分。固定测试记录接收步序列，以相同序列比较 30/60/144 FPS；不承诺不同网络到达顺序也逐位一致。
- 低延迟候选和击球时姿态来自待实现 F7；当前结束摘要只有 start/end orientation，不能当作峰值拍面。教学/正式局使用同一新鲜度门，THROW 不能冒充尚不存在的 SWING/发球课程。

## F6 球物理与规则边界

坐标米、秒、rad，Y 向上；球心/速度/角速度/固定步编号为唯一动态状态。F6 以 `h=1/120 s` 积分，重力初值 9.81 m/s²，加二次空气阻力、限幅马格努斯力和旋转衰减，系数带单位并留在公共参数中。
一局只推进一份球；渲染插值，所有相机/机器人共享快照，不能每视口各积分。使用项目的 delta 累积器或主线统一步进入口，不改全局物理频率；暂停不积压，掉帧不丢时间/跳过截止事件，积压超预算视为性能失败。
连续碰撞需求：扫掠球体与有限台面/台侧、网带/网面/网柱、地面/场界，以及移动球拍的相对轨迹，求最早接触时刻；一次子步可消费多个碰撞及剩余时间，设有限迭代与接触分离容差。
不能只检测末点、用无限台平面代替矩形台面、仅因越过网平面即擦网，或靠肉眼可见网孔放球穿过。台网视觉变形不改变权威碰撞面，交付时检查二者误差与边缘案例。
接触输出至少含球/接触 ID、固定步内时刻、接触体/台区、点/法线、入出速度/旋转及击球者；反弹恢复系数与切向摩擦按球台/胶皮/网分类，T2 用固定输入锁定，不在规则类重复实现。
预测接口必须在状态副本上使用同一积分/碰撞参数，返回落台点、到达时间、过网高度或不可达；不得推进真实球、消耗比赛 RNG 或偷偷使用不同简化弹道。跨平台比较容差，不承诺逐位确定性。

## 机器人、教学与单人

三档只改决策误差，不改球/球拍速度上限和合法顺序；独立 RNG 按比赛种子与参赛 ID 派生。机器人从已观察球状态调用 F6 预测，经过反应延迟再提交同一击球命令，不读真人未来输入、不伪造传感器峰。

| 档位 | 反应延迟 | 目标落点误差范围 | 旋转利用比例 | 可扣杀时选择概率 |
|---|---|---|---|---|
| 简单 | 0.24 s | ±0.192 m | 0.20 | 0.05 |
| 普通 / 补位 / demo | 0.16 s | ±0.080 m | 0.55 | 0.20 |
| 困难 | 0.10 s | ±0.028 m | 0.85 | 0.40 |

误差初值为 `0.08 m × bot_error()`（当前为 2.4/1/0.35）；`bot_ability()` 正式单人为 0.62/0.90/0.99、非 solo 为 -1，不能把 -1 直接当概率。旋转/扣杀按上表常量，不借 difficulty 改判定窗口。
教学需求由主线 `RSTutorial` 增加通用 SWING 与“B 抛球→下降拍击/松开辅助”的发球步骤：先示范再要求新鲜练习，显示早/好/晚、接球者与轮次；短按/旧峰不能通过。
正式单人继续 `RSSolo.begin(id, slot, difficulty)`，真人缺席不自动开局，其他手柄不乱入；纪录/星数规则按前节，三档误差分布和可玩性须分别验收，不能用单次机器人胜负宣称难度已调好。

## 镜头、HUD、开场、回放与领奖

相机沿用 `p.cam`，球台后上方看全台，平滑横移而非追手柄抖动；同队镜头略错位，场地/双方人物/球放共享世界层，个人提示才放自身层。安全边界保证不穿台、不被队友遮住球。
开场 `RSIntro.apply/fade` 7 s（4 s 场馆→球台→持拍肩后，末 3 s 公共倒数），暂停冻结、重开归零；无公共跳开场接口时不虚构 A 跳过。分间只 0.8 s 小演出，不重复开场。
HUD 用 `draw_text/draw_pill/draw_box/draw_clock`、RSUi 字体/颜色；主要显示双方原始比分、发球者/接球者、剩余时间、“该你接”和早/好/晚，终局另解释胜利奖励，不能把 3100 当比赛比分。
队伍/击球者同时用名称、P 槽号/图形及颜色，不能只靠颜色；中英文走 `tr/RSLang.t`。125% 字号优先保留比分/轮次/时限，次要教学提示换行或收起，不缩字号掩盖溢出。
`camera_shake=false` 关闭震动和扣杀推近，仅保留稳定跟随；冲击圈/拖尾不遮球、低闪烁，视觉开关不得改变球/输入窗口/RNG。画质、环境与视口沿用 `RSSettings`。
精彩片段选择纯函数：按“扣杀直接得分优先、合法击球次数更多、回合开始更早”依次比较，全部无合法片段则直接领奖。活动回合保留末 4 s 的滚动候选；回合结束且优于已存最佳时，将候选冻结为最佳片段，之后滚动不得覆盖它。两缓存各≤480帧、合计≤2 MiB，仅存球/四人动作参数/相机快照，不存整套骨骼字典；T7 实测内存。
回放用 `RSReplay.reset/sample` 在 RESULTS 同步采样所有视角，0.5 倍速最多 8 s；不推进 F6/规则、不收输入、不二次计分/记纪录，不改全局时间缩放；声音只消费新跨越事件。无片段不等待空回放。
回放后 0.3 s 缓冲，再 1.6 s 领奖入镜；结果面板延迟最多 9.9 s。F5 队伍领奖契约需支持两成员同台/并列、与队伍成绩一致；不伪造个人分数数组来掩盖队伍语义。

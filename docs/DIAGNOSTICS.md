# 中枢日志与输入录制

本阶段处理 [#47](https://github.com/cb8010d6/sport-games/issues/47) 的日志与录制问题，不改变设备配对、游戏协议或存档。局域网状态接口与手机鉴权由 [#44](https://github.com/cb8010d6/sport-games/issues/44) 另行处理。

## 日志

- 便携版启动器只收集自己启动的中枢输出，位置为当前用户的 SportGames 数据目录。复用已运行的中枢时，不接管或终止它，也不打开日志。
- `hub.log`、`hub.log.1`、`hub.log.2` 各不超过 1 MiB，总计最多 3 MiB。运行期间持续轮转，保留最新输出；每次启动中枢写入时间分隔头。旧版超大文件在打开时仅保留末尾 1 MiB，历史文件不会重新脱敏。
- 发行打包检查同时拒绝带额外后缀的日志 / 录制备份，例如 `hub.log.1` 与 `inputs.jsonl.backup`，防止只按最后一个扩展名检查时漏过。
- 中枢的默认日志和 `-v` 日志均隐藏 MAC 与平台 BLE UUID，包括第三方日志和异常堆栈中的地址。连接 / 断开日志使用临时控制器编号，不写设备名称。运行时的配对 key、设备名称与旧固件显示名称不变。
- 扫描失败、每个控制器的命令队列满警告分别最多每 60 秒报告一次；下次报告附上自上次报告以来的次数。没有后续失败时不额外刷出汇总行。
- 日志磁盘写入失败后，启动器继续排空输出管道，避免阻塞中枢；游戏退出后报告写入错误。启动失败仍按原流程显示错误，并停止自己启动的中枢。

这些措施不代表日志没有其他个人信息：局域网 IP、文件路径以及旧版日志仍需在分享前检查。直接从命令行运行中枢时，日志仍输出到终端；自行重定向的文件不由启动器轮转。

## 输入录制

`--record` 仍向指定 JSONL 追加原始体感与按键数据，不额外产生文件。

- `c` 变为“随机录制会话 / 类型-编号”，例如 `<session>/phone-2`。设备断线重连继续使用同一编号。
- `n` 使用同一匿名别名，不再保存设备名或昵称，避免名称本身包含地址或 client_id。
- 每个 Recorder 使用新的随机会话；重新向同一文件追加时，不会把不同会话的第一个设备合并成同一个回放手柄。对照表仅在进程内存中存在。
- 采样时间、原始传感器数值、按键和拨轮格式不变。回放支持新格式和已有的 key / name 格式，不重写旧录制。

原始动作数据仍是调试资料，不应提交到仓库。已有录制不会自动清理个人信息。

## 验证边界

专用测试覆盖模拟 BLE 成功 / 失败 / 旧固件断开、异常格式化、警告限流、录制重连与追加、旧格式回放，以及真实子进程的大量 stdout / stderr、日志轮转、写入失败和启动器所有权。没有使用实体 Regina、手机传感器或 BLE 适配器；这些测试不能证明真机手感、BLE 重连质量或 GPU 性能。

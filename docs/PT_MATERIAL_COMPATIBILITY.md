## 光栅与 RT 的计算

两份 shader 只在现有 `#if defined(RT)` 路径使用替代计算。普通光栅路径保留原有
`fwidth` / `dFdx` / `dFdy`，不改变贴图、色彩、材质参数、场景、框架或存档。
共用的 [rt_pixel_footprint.gdshaderinc](../game/shaders/rt_pixel_footprint.gdshaderinc)
避免两处投影估算发生偏差，没有增加第三方运行依赖。
相机位置、逆视图矩阵、投影矩阵和视口大小只在 `fragment()` 中读取，再作为显式参数传给
纯计算 helper。立面 `fragment()` 还一次计算局部足迹，作为第四参数传给所有 `box()` 调用；
`box()` 的 RT 分支不直接读取 `NORMAL`、`TANGENT` 或 varying。光栅分支忽略这个足迹参数，
仍计算原来的 `fwidth(p) * 0.75`，不是用零导数代替抗锯齿。

公共计算用投影矩阵的 X/Y 缩放、当前视口分辨率和相机深度求一个像素的世界空间跨度，
再沿相机射线将两个相机平面偏移解析投影到命中点的局部切平面。结果是在指定世界单位轴上
两个偏移绝对值之和，单位为米/像素；透视随深度增长，正交不随距离增长。
视线与法线夹角趋于掠射时，将有符号余弦的绝对值限制在至少 0.05，避免无界除法。

- 立面的矩形遮罩以该足迹替代 `fwidth(p)`，保留原来的 0.75 宽度系数、窗框和店铺细节。
  室内映射的 U 方向改读实际 UV 切线，不再用屏幕导数判断方向。
  `RSSkateCourse._quad_uv()` 为墙面逐角设置米制 UV；`_commit()` 对这些 ShaderMaterial
  调用 `SurfaceTool.generate_tangents()`，因此这里使用的是网格 UV 切线，不是假定的默认轴。
  NVIDIA 引擎的 RT 命中路径插值该切线并提供视图空间 `TANGENT`；转回世界空间后可正确区分
  街道两侧、建筑前后与两端墙的 U 方向。此约定依赖现有立面网格的有效 UV 与切线。
- 滑雪细纹的相位为 `wpos.x / 0.045`。将世界 X 轴足迹除以 0.045 米，得到每像素覆盖的周期，
  继续用原有 0.25–0.8 周期的平滑阈值衰减高频条纹。压雪、粉雪、岩石贴图、法线与光照仍保留，
  没有将导数设为恒零或用纯色材质掩盖失败。

这只是以当前主相机和局部平面为依据的一阶近似，不是从光线路径传播的完整 ray differentials。
它不包含次级反射/折射光线的累计足迹、粗糙度扩散或遮挡边界，掠射限制也会低估极端角度的覆盖。
纹理采样的 LOD 机制没有在本次修改中重写；不能据此宣称消除了所有混叠、闪烁或画质差异。

## 已发生的前端编译失败

BCC 引擎的第一轮真实 PLAY 测试记录 `bcc08cc81c-20261026T111614Z-4136ec` 中，
滑板 map0 与滑雪 map0 的 PT+RR 两例均为 **FAIL**。进程虽退出 0，日志仍报告 include 第 5 行
的 `INV_VIEW_MATRIX` 未知，随后进入 RT 预处理回退；不能将该轮截图或退出码当作材质通过。
原始日志、矩阵及冻结输入核对保留，没有把原 FAIL 改写成成功。

此前只检查最终 GLSL 全局变量是否可见，漏掉了先执行的 Godot shader 语言前端作用域检查。
本次修正将阶段内建取值移到 `fragment()`，helper 只接收显式参数；也移除了 `box()` helper
对阶段内建与 varying 的直接访问。后续 A738 真实运行是独立复验，没有覆盖这轮原始失败记录；
静态文本核对本身仍不等于前端或 GPU 编译通过。

## 引擎修复范围

实例内建从实际几何与 MultiMesh 实例读取 `INSTANCE_ID`、`INSTANCE_CUSTOM` 和颜色，
没有用常量零伪装支持；需要实例语义的 shader 使用独立 TLAS 实例，避免合并路径丢掉实例信息。
写入 `VERTEX` 的位移结果按几何 owner 隔离，两个共享同一 MultiMesh、但具有不同材质或世界变换的
节点不再共享首个 owner 的位移结果。新 owner、释放 owner、可见数量收缩 / 增长和材质变化
由独立最小夹具检查；这些引擎修复与本游戏的导数分支是不同修改，不能相互代替。

标准材质启用顶点色作为反照率时，原 PT 合并材质路径会漏掉颜色，真实游戏遮阳棚因此显示白色。
A738 将符合条件的不透明标准材质转入完整生成的 custom hit group，使用实际 `COLOR` 及其 sRGB
转换语义；普通网格和 MultiMesh 均有颜色夹具。这修复的是颜色传递，不是补回缺失贴图。
MultiMesh 的这条路径需要展开实例，增加 TLAS 实例数与相关资源开销；没有建立性能无回归结论。

该标准材质路由只覆盖保守的不透明子集。透明、alpha 裁剪 / 混合、折射、发光材质仍走原路径；
发光排除用于保留现有网格光源采样约定。覆盖位置或模型视图 / 投影矩阵、粒子拖尾、点大小、
heightmap / parallax 等高级路径也被排除，不能据此宣称全部 StandardMaterial3D 已兼容 PT。
其他任意 shader 的屏幕导数不会由引擎自动转成 ray differentials。

## 剩余验证边界

冷启动的异步 shader 编译在 hit group 尚未就绪时仍可能显示灰色占位。同步编译独立对照中，
原生命周期的“移除顶点位移材质”阶段恢复正常；这只确认该阶段与异步等待有关，
不证明全部冷编译路径无灰色或无竞态。旧严格九阶段用例的失败输入与回执保留，
不能用后续新增颜色路由的不同 TLAS 预期改写原结果。

仍需专项扩展立面左右 / 背面 / 两端、近远距离及掠射视角的画质比较，滑雪前进 / 换图 / 重开，
不同 FOV、分辨率和 1 / 2 / 4 人视口下的足迹尺度，以及正交投影不随距离变化的独立检查。
本轮没有重写纹理 LOD，也不据短时画面保证所有细纹、法线、反射与透明物质量。
`Projection::invert` 历史诊断与其他未测 shader 不能因这两份材质通过而关闭。

Vulkan SDK 严格验证仍未干净，材质生命周期的 `PRESENT_AFTER_WRITE` 同步诊断和此前的
`09600` / `03868`、FG 内部诊断保持独立问题。普通游戏画面通过不能代替严格验证。
实验仍非 RC，其他限制见 [RTX_EXPERIMENT.md](RTX_EXPERIMENT.md)。

本次源代码适配由 OpenAI Codex 辅助完成；没有新增素材、二进制或第三方依赖，既有许可不变。

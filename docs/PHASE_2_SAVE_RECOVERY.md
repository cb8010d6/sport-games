# 第二阶段：存档版本与恢复

范围：四个本地档案、个人最佳纪录、显示 / 音量设置。保留现有公开接口和 `.cfg` 路径；`RSSettings.save()` 现在返回 `Error`，旧调用方仍可忽略返回值。

`RSSave` 读取顺序是原文件、上一份有效 `.bak`、完成写入的 `.tmp`。版本 0 是没有元数据的旧格式；版本 1 在 `_save` 段记录版本和规范化 ConfigFile 内容的 SHA-256。校验检测意外损坏，不防作弊。成功保存前先保存有效旧副本，再写入、重新读取验证临时文件，最后提升为原文件。恢复读取不立即覆盖原文件，下一次成功保存才修复它。

发现不支持的新版本时，写入会重新检查原文件及恢复副本并拒绝覆盖，避免旧构建毁掉新构建的数据。无效字段按类型和范围回退；排行榜过滤无效槽、负分并保留每槽最高分。档案保存失败时回滚内存中的编辑和手机昵称。

验证使用临时用户目录中的真实文件，包含旧格式升级、校验不符、无效元数据、空文件、超大文件、语法损坏、仅剩临时文件、替换间隙、所有副本损坏、写入失败、新版本保护、档案回滚及旧设置迁移。`python tools/test_game.py --party` 自动运行本阶段测试，因此现有 Linux CI 和 Windows 打包检查都会覆盖它。独立执行：`python tools/test_storage.py`。

故障测试刻意产生两条诊断：固定损坏夹具的 ConfigFile 语法错误、未来版本档案的保存错误。运行器要求它们各出现一次，并拒绝其他引擎错误、脚本错误、崩溃、泄漏或缺失完成标记。62 项文件检查通过后，再启动独立进程读回纪录、设置，并确认引擎能读取带版本元数据的启动覆盖文件。

边界：未做真实断电或磁盘硬件故障测试。Windows 文件替换存在间隙，依靠备份恢复；不承诺磁盘级原子性。设置和派生的 `override.cfg` 是两个文件，不是跨文件事务；任一写入失败会返回错误。Godot 在游戏脚本执行前自行读取 `override.cfg`，此时不会调用本恢复模块；损坏的启动覆盖文件由引擎诊断，此时不保证回退备份，游戏下一次保存设置时才会重建它。所有副本均失效时使用默认值，日志保留原因。4 MiB 是单份配置的读取上限。
